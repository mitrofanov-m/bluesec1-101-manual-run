BLUESEC OVERVIEW

Как устроено соревнование

BlueSec — симулятор работы автономного SOC-аналитика. Агент получает алерт, исследует связанные события и должен доказательно решить: это настоящая атака или ложное срабатывание.

  1. 01Получить алерт

    Условие, несколько сущностей и иногда связи между ними.

  2. 02Исследовать граф

    Один вызов инструмента за шаг и оценка каждого результата.

  3. 03Отправить вердикт

    Вывод вместе с проверяемыми доказательствами.

Граф расследования

Данные представлены как сущности — хосты, процессы, файлы, пользователи и сетевые адреса — и связи, описывающие действия между ними: запуск, запись файла, вход на хост или соединение.

учётная запись→вход на хост→процесс→файл→соединение

Главная сложность

Алерт — начальная гипотеза, а не доказательство атаки. Необычный процесс на сервере может быть вторжением, штатным обновлением или работой администратора. Контекст помогает проверить версию, но не заменяет доказательства.

С чем столкнётся агент

С процессами, файлами, сетью, реестром, службами, PowerShell, Active Directory, почтой, VPN, SMB, Windows- и Linux-событиями. Конкретный набор инструментов и данных объявляет сама среда задачи.

Что требуется в финале

malicious

Указать подтверждённые артефакты и нужные действия реагирования: изоляцию, блокировку, удаление или смену учётных данных.

benign

Сослаться на конкретные свойства сущностей и связей, которые подтверждают легитимность активности.

Как оценивается результат

quality_score отражает правильность вывода и качество доказательств, а efficiency_score — экономность пути. Лучшее расследование не собирает всё подряд, а находит короткую доказательную цепочку без повторных и бесполезных вызовов.

AVAILABLE TOOLS

Инструменты расследования

Среда показывает только разрешённые для текущей задачи инструменты. Каждый вызов читает данные либо завершает расследование.

get_entity

Показывает подробности одного объекта по entity_id: процесса, компьютера, пользователя или файла.

Практический пример

Если свойства процесса уже есть в алерте, get_entity может не добавить деталей, но вернуть новые relation_ids. Эти связи становятся следующими точками расследования через get_relation.

get_relation

Показывает связь между двумя объектами по relation_id, включая её направление и свойства.

Когда инструмент полезен

Вызывать get_relation для связи, уже выданной в исходном алерте, обычно нет смысла: среда может вернуть те же самые поля без новой информации. Инструмент становится полезен позже, когда get_entity или другой шаг обнаружил новый relation_id. Тогда по нему можно загрузить ещё не показанную связь и продолжить расследование от связанных объектов.

search

Ищет сущности и связи по фрагменту имени, пути, ID или другого известного значения.

get_ad_object_info

Получает сведения об объекте Active Directory по найденному ad_object_id.

Практический пример

Для доменного хоста инструмент может уточнить его назначение, подразделение, серверные роли и статус контроллера домена. Такой контекст помогает оценить активность, но сам по себе не доказывает её безопасность.

finish_investigation

Отправляет финальный вердикт и безвозвратно завершает текущую задачу.
