# Идея проекта

## Контекст

[BlueSec](https://bluesec.team/?lang=ru) — соревнование по расследованию реальных и смоделированных киберинцидентов с помощью AI-агента. Агент получает задачу от платформы, запрашивает данные, анализирует телеметрию и другие артефакты, а затем отправляет обоснованный вердикт. Решение оценивается как по качеству расследования, так и по эффективности — количеству обращений к инструментам.

Я не являюсь специалистом по кибербезопасности, но хочу на практике разобраться, как устроены соревнование, его задачи и процесс расследования инцидента.

## Технические ограничения платформы

При работе с [платформой BlueSec](https://bluesec.team/) необходимо учитывать следующие ограничения:

- один участник может одновременно держать не более 10 активных запусков (`runs`);
- в рамках одного запуска одновременно может выполняться только одна задача;
- один участник может создать не более 10 запусков за 30 минут в рамках одного этапа соревнования;
- для одной задачи доступно не более 100 вызовов инструментов; после достижения лимита задача автоматически завершается;
- запуск автоматически закрывается после 15 минут без запросов от клиента; проверка выполняется раз в минуту, поэтому фактическое закрытие может произойти через 15–16 минут неактивности;
- 15 минут — не общий лимит времени на расследование, а максимально допустимая пауза между запросами клиента; каждый новый запрос сбрасывает таймер неактивности;
- с учётом лимита в 100 вызовов инструментов теоретическая продолжительность одного расследования может достигать `15 × 100 = 1500` минут, то есть 25 часов; для сравнения, таймер в 30 или 45 минут увеличил бы этот предел до 50 или 75 часов соответственно;
- при штатном завершении клиенту рекомендуется явно закрывать запуск, чтобы сразу освободить занятый слот; закрыть активный запуск можно как через клиент, так и через веб-интерфейс платформы.

Проектируемый веб-интерфейс должен учитывать эти ограничения: показывать пользователю состояние и число активных запусков, не допускать параллельного выполнения задач в одном запуске, отображать расход лимита вызовов и время неактивности, а также явно закрывать запуск после завершения работы.

## Идея

Создать веб-интерфейс, через который человек сможет вручную пройти и решить одну из задач BlueSec.

Вместо полностью автономного агента пользователь будет сам управлять расследованием: изучать описание инцидента, запрашивать доступные данные, просматривать полученные артефакты, фиксировать наблюдения и в конце формулировать вердикт. Интерфейс должен объяснять происходящее простым языком и помогать человеку без опыта в кибербезопасности двигаться по задаче осмысленно.

Проект нужен прежде всего как учебный инструмент: он должен сделать внутреннюю механику BlueSec наблюдаемой и понятной, а не пытаться сразу создать наиболее эффективного соревновательного AI-агента.

## Что должен позволять веб-интерфейс

- подключиться к рантайму BlueSec с использованием выданного токена;
- получить одну задачу расследования;
- увидеть условие задачи и доступные действия;
- вручную вызывать инструменты и запрашивать данные у платформы;
- удобно просматривать ответы, телеметрию и артефакты;
- сохранять историю действий и промежуточные выводы;
- при необходимости получать понятные подсказки и объяснения терминов;
- сформулировать и отправить итоговый вердикт;
- показать пользователю полный путь расследования и полученный результат.

## Предполагаемый пользовательский сценарий

1. Пользователь запускает приложение и подключается к BlueSec.
2. Приложение получает задачу и показывает её в понятном виде.
3. Пользователь выбирает действие или запрос к серверу.
4. Интерфейс отображает полученные данные и объясняет их назначение.
5. Пользователь последовательно собирает контекст инцидента и фиксирует гипотезы.
6. Пользователь формирует обоснованный вердикт и отправляет его на проверку.
7. Приложение показывает результат и историю расследования, чтобы можно было понять ошибки и повторить попытку.

## Критерий успеха первой версии

Человек без специальной подготовки в кибербезопасности может через веб-интерфейс пройти одну задачу BlueSec от получения условия до отправки осмысленного итогового вердикта и при этом понять основные этапы расследования.

## Запуск исходного агента

Для изучения протокола взаимодействия и проверки интеграции можно использовать открытый пример агента:

```bash
git clone https://github.com/False-Positive-Community/bluesec1-agent.git
cd bluesec1-agent
uv sync
cp .env.example .env
# В .env нужно указать SCENARIO_RUNTIME_TOKEN, выданный в личном кабинете,
# а также LLM_BASE_URL, LLM_API_KEY и LLM_DEFAULT_MODEL.
uv run --env-file .env bluesec1-agent
```

Репозиторий примера: [False-Positive-Community/bluesec1-agent](https://github.com/False-Positive-Community/bluesec1-agent).
